# Asset licences

Every font, image, icon and design file in `public/` and `design/`, with who made it, where it came
from and what the licence requires. Owner answers are dated in [`business-facts.md`](business-facts.md)
(Brand assets). `python3 tools/check_site.py` (check `asset-inventory`) fails if a file in
`public/assets/img/`, `public/assets/fonts/` or the root icon files is not named here.

Contracts, permissions and source files stay outside the repo. The Evidence column says where.

## Rights by creation method (2026-09-29)

No image was made by a freelance designer or a logo-maker or template tool (owner answer, business-facts Brand assets), so no signed copyright assignment is needed and no tool licence applies. If that answer is wrong, say so: a designer-made logo needs a signed copyright assignment, and a template-tool logo needs that tool’s current licence (commercial use, exclusivity, trademark registration) checked. Owner-made: logo. AI-made (Claude Code): OG image, icons. Client’s: the Grisha.studio screenshot.

## Showing client work

Rules for any client work shown on the site (Grisha.studio today):

1. Show a client’s screenshot, name or artwork only with the client’s recorded permission. Record the answer and date in `business-facts.md` (Case study) and keep the message outside the repo. The same rule is in “Portfolio-use rights” in `business-facts.md`.
2. Don’t copy photos or artwork the client owns into other pages, ads or the site’s own design. Use only what the permission covers.
3. Give the photographer or artist credit where the client’s licence for the image requires it. Ask the client for the licence terms before publishing.
4. If the client withdraws permission, remove the image and the case study.

Rights findings above are summaries of sources, not legal conclusions. Where ownership is unclear the Status says “attorney to confirm”.

## Adding an asset

1. Add a row to this table before the asset goes into the repo, with creator, source, licence and where the proof is kept.
2. Prefer self-made work, then SIL OFL, CC0 or MIT material. Anything else needs the owner’s approval and a written licence.
3. No hotlinking: host every font, image and icon in `public/assets/`. The CSP and `no-external-resources` check enforce this.
4. Keep the licence file beside the asset when the licence requires it (as for the OFL fonts), and add an icon set’s notice to `public/assets/LICENSES.md` when its licence asks for one.
